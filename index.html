There's more to Apache Wicket

Wicket Stuff is a collection of open source components and integrations for the Apache Wicket web framework. Created by the community around Wicket, released in step with every Wicket version, and available from Maven Central.

How it works

Community projects, one release train

Wicket Stuff is a container for Wicket-related projects. Authors bring the code; the release process makes sure every project ships for every Wicket release.

Released in step with Wicket

The version tells you which Wicket it is built for. {{ site.releases.lts.version }} pairs with Wicket {{ site.releases.lts.wicket }}, {{ site.releases.current.version }} with Wicket {{ site.releases.current.wicket }}. No compatibility guesswork.

One BOM for everything

Import wicketstuff-bom and declare modules without a version. All artifacts are on Maven Central, almost all under org.wicketstuff.

Open to every Wicket project

The bar is low on purpose: if it is related to Wicket, it is welcome. Wicket Stuff code is mostly Apache License 2.0; integrations bring in third-party libraries under their own licenses. Most modules ship with a runnable examples application.

Get started

Up and running in three steps

Wicket Stuff modules are plain Maven artifacts. If your project builds with Maven or Gradle, you are ready.

Match your Wicket version

Use the Wicket Stuff release with the same major version as Apache Wicket. Wicket {{ site.releases.lts.wicket }} is the long-term support line; {{ site.releases.current.wicket }} is the current feature line. See the version table.

Wicket {{ site.releases.lts.wicket }}.x LTS  →  Wicket Stuff {{ site.releases.lts.version }}
Wicket {{ site.releases.current.wicket }}.x      →  Wicket Stuff {{ site.releases.current.version }}

Import the BOM

The bill of materials manages the versions of all Wicket Stuff artifacts, so they always fit together.

<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>org.wicketstuff</groupId>
      <artifactId>wicketstuff-bom</artifactId>
      <version>{{ site.releases.lts.version }}</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>

Add the modules you need

Copy an artifact id from the module list and add it without a version. An id with a colon, like org.wicketstuff.scala:wicketstuff-scala, is groupId:artifactId. Javadoc JARs are published next to each artifact on Maven Central. Still on 9.x? There is no BOM: give each dependency version 9.25.0.

<dependency>
  <groupId>org.wicketstuff</groupId>
  <artifactId>wicketstuff-shiro</artifactId>
</dependency>
Versions

Which release do I need?

Each Wicket Stuff line follows an Apache Wicket major version and inherits its Java and servlet requirements. Apache Wicket publishes its own support schedule.

Apache Wicket 8 and 9 reached end of life on 29 October 2026 and get no more releases; 9.25.0 is the final Wicket Stuff 9.x release. Wicket {{ site.releases.lts.wicket }} is the long-term support line, supported until {{ site.releases.lts.supported_until }}; it is the default for the snippets and documentation on this site. Each line has its own page with its requirements, BOM snippet and the modules it added and removed. Since Wicket 11 a new feature line ships every quarter, and every fourth one is a long-term support release. Older releases for Wicket 8, 7, 6, 1.5 and 1.4 remain available on Maven Central. Development of the next major happens on master. Release notes are on the GitHub releases page.

Report a bug

Help us help you. A good report gets fixed much faster.

  1. Reproduce the bug with the least amount of code.
  2. Write a unit test or a quickstart application that shows it.
  3. Even better: fix it and open a pull request.
  4. File the result in the right tracker: wicketstuff/core for Wicket Stuff modules, apache/wicket for Wicket itself.
Open an issue View open issues

Report a security issue

Report vulnerabilities privately, not as a public issue, so a fix can be released before the details are public.

  1. Describe the vulnerability, the affected module and versions, and how to reproduce it.
  2. For a Wicket Stuff module, use GitHub's private vulnerability reporting on wicketstuff/core.
  3. For Apache Wicket itself, contact the Apache Wicket security team.
